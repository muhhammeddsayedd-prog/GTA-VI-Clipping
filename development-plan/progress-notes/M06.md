- `src/sixstars/factory/commands.py` and the `clip` group in `cli.py`: `sixstars clip render-file` and `sixstars clip render`.
- `src/sixstars/storage.py`: `ClipStorage` (upload with upsert, delete, signed URL) and `FakeClipStorage`.
- Assets: `assets/fonts/` (Montserrat Black, Noto Emoji, both OFL 1.1 with licence files), `assets/sfx/pop.wav` with `LICENSES.md` (made by a script for this project, CC0), `assets/brand/` (gold six-pointed star on `#0D0D12`: `star.png`, `logo.png`, `logo.svg`).

### Public API (what M07, M08 and M14 call)

```python
from sixstars.factory import pipeline
from sixstars.factory.pipeline import RenderInput, Deps

pipeline.render_clip(item: RenderInput, *, deps: Deps | None = None, force: bool = False) -> str   # clip id
pipeline.upload_clip(clip_id, *, storage=None) -> str            # storage key; call after the gate passes
pipeline.mark_failed(item, error) -> str | None                  # closes the row after the last attempt
pipeline.register_handlers(job_types=("clip.render", "express.render"))
pipeline.set_after_render(job_type, callback: Callable[[clip_id, Job], None] | None)
pipeline.handle_clip_render(job); pipeline.handle_express_render(job)

RenderInput(
    source_path: Path,              # the section file (VOD lane) or the buffer cut (live lane)
    window_start_s, window_end_s,   # seconds in that file
    creator: str,                   # handle for the credit and for P2
    spike_floor_s=None,             # latest allowed clip start, seconds in the file (default: window start)
    creator_id=None,                # required by render_clip (clips.creator_id, layout cache)
    platform="youtube", source_id="", source_url="", source_type="vod",   # clips columns
    lane="hourly", mode="normal",   # lane: "spike" | "hourly"; mode: "normal" | "express"
    stream_title="", spike_id=None, clip_id=None,
    pad_start_s=None, pad_end_s=None,   # what is transcribed and offered to P2; default window +/- spikes.context_pad_s
    source_offset_s=0.0,            # where the file starts in the original video or stream
    verdict: SpikeVerdict | None = None, chat: tuple[ChatLine, ...] = (),   # chat t_s in seconds in the file
    upload=False,
)
RenderInput.to_payload() -> dict       # the JSON job payload
RenderInput.from_payload(payload, default_mode="normal")

from sixstars.factory.commands import input_from_spike
input_from_spike(spike_id, source_path, *, source_offset_s=0.0, lane=None, mode=None, window=None, upload=False) -> RenderInput
```

**Job types and payloads.** `clip.render` (queue `normal`) and `express.render` (queue `express`) take `RenderInput.to_payload()`. When the payload has no `mode`, `clip.render` means `normal` and `express.render` means `express`; without `lane`, `express.render` means `spike`. Enqueue with a `dedupe_key` (for example `clip.render:<spike_id>`). `register_handlers()` must be called where the worker starts (see "Changes needed in other files").

**Idempotent.** The clip row is found by `clip_id` (a uuid the caller chooses) or else by `spike_id`. A second call returns the same id: a finished clip (`gating`, `rejected`, …) is not rendered again; a row still in `rendering` is rendered again under its first series number. The number comes from `nextval('clip_series_seq')` in the insert of the row, so a retry never takes a second one. Without `clip_id` and `spike_id` every call makes a new clip.

**Status flow.** `rendering` → `gating` (file at `$DATA_DIR/ready/<clip_id>.mp4`), or `rendering` → `rejected` with `reject_reason` `no_speech`, `writer: <reason from P2>` or `render_failed: <error>` (after the last job attempt; the spike becomes `failed` and a `warn` notification is sent). Spike row: `rendering` and `clip_id` at the start, then `clipped`, `rejected` or `failed`. Other errors are raised and leave the row in `rendering` for the retry. `BudgetExceededError` (VOD lane over `ai.daily_budget_usd`) does not fail the job: the same payload is queued again for 00:02 UTC and the event `clip.render_deferred` is written.

**Events.** `clip.render_started`, `clip.rendered`, `clip.rejected`, `clip.render_failed`, `clip.uploaded` (entity `clip`), `clip.render_deferred` (entity `job`).

**What is stored on the clip row when a render ends in `gating`:**

| Column | Content |
|---|---|
| `series_no` | From `clip_series_seq`, shown on the end card. |
| `start_s`, `end_s` | The final cut as positions in the original video (`source_offset_s` + file time). |
| `duration_s` | Clip length **without** the end card. The file is `factory.end_card_s` longer. |
| `transcript` | `{"language": "en", "words": [{"w", "s", "e"}]}`, **in clip time** (0 = first frame of the clip), only the words of the final clip, English. |
| `original_language` | ISO code of the speech (`en`, `es`, …). |
| `hook`, `title`, `caption`, `hashtags`, `commentary`, `topic`, `spoiler`, `score` | P2 outputs. |
| `keywords` | `{"<line number>": ["word", …]}` as P2 gave them. |
| `safety_flags`, `score_parts` | The P2 objects as JSON. |
| `music_ratio` | Share of 1-second frames flagged as music (0 to 1). **NULL means the detector could not run**: the gate must treat that as unknown, not as 0. |
| `profanity_count` | Words bleeped in the clip. |
| `gate_profile` | `express` for lane `spike`, else `hourly`. |
| `local_path`, `file_size_bytes`, `render_ms` | The file; `render_ms` is the loudness pass plus the encode. |
| `storage_path` | Set by `upload_clip`: `clips/<env>/<yyyy>/<mm>/<dd>/<clip_id>.mp4`. |

The P2 outputs are also stored on a clip that P2 rejected. The details that have no column are in the `data` of the `clip.rendered` event: `music` (`ratio`, `frame_s`, `frames` as 0/1 per second, `detector`), `bleeps` (spans in clip time), `sfx_times_s`, `layout`, `timings_ms` per stage, `transcriber`, `translated`, `file_duration_s`, `nvenc`.

### CLI

```
sixstars clip render-file <video> --start 12 --end 48 --creator test --lane hourly
        [--mode normal|express] [-o out.mp4] [--hook TEXT] [--keyword WORD ...] [--facecam x,y,w,h]
        [--layout auto|b] [--series-no 1] [--whisper-model small] [--set key=json ...] [--stills DIR]
        [--no-music] [--ai] [--title TEXT]
sixstars clip render <spike_id> --source <file> [--source-offset S] [--lane spike|hourly]
        [--mode normal|express] [--upload] [--force]
```

`render-file` writes no clip row. Without `--ai` it needs no database and no key: documented default settings, the window as given, hook and keywords from the options, layout B unless `--facecam` is given. With `--ai` the settings come from the table and P2 and P4 run. `--stills` saves frames at 1 s, 5 s, the middle and the end card. `render` runs the whole pipeline for a stored spike; the source file must be given, because downloading it is the VOD lane's job.

### Real-footage check (2026-11-17)

Two 80-second, 1080p60 sections of public GTA 5 videos fetched with yt-dlp (`--download-sections`): a racing stream with a facecam in the top-right corner (swearing) and a role-play video with no facecam. Each went through the whole pipeline against the **staging** project: transcription, P2, P4, music detection, render, and for two of them upload to the private bucket (a signed URL then returned the file). One run was started with `sixstars clip render <spike_id> --source … --upload`, the others with `render_clip`. Local transcription used the `small` model instead of `medium` (a 1.5 GB download on this machine), passed to the transcriber for the test; the `vod.whisper_model` setting on staging was not changed. Machine: a Windows 10 desktop, CPU only, ffmpeg 9.0.2. **Nothing was measured on the staging server.**

| facecam, spike lane | A | express (`superfast`) | hosted `whisper-1` | 27.5 s | 1.7 + 7.9 = 9.6 s | 40 s | 21.6 MB | -13.8 LUFS | -2.6 dBFS |
| facecam, hourly | A | normal (`veryfast`) | local `small` | 31.5 s | 13.4 s | 54 s | 23.8 MB | -13.9 LUFS | -2.3 dBFS |

Stage times of the express facecam clip: transcription 9.7 s (80 s of audio sent to the hosted API), P2 3.8 s, music 14.1 s, P4 3.1 s, render 9.7 s. Music detection is 10.6 s the first time in a process (loading the model) and 0.8 s after that, so a long-running worker spends about 27 s on such a clip. P4 runs once per creator and resolution in seven days (0.15 s from the cache). Local transcription with `small` took 26 to 43 s for 80 s of audio, including loading the model. Upload of a 21 MB file took 37 to 38 s on this connection.

**Layout.** P4 found the facecam at `x 1434, y 0, w 486, h 273` (confidence 0.93 to 0.95 over three detections) and none in the other video (0.90 to 0.93). The facecam crop is tight on the webcam; the gameplay crop slides left so the webcam overlay is not in it.

**Bleeps.** Five bleeps across the two facecam clips ("fucking" three times, "twat" twice). Inside every span the audio outside the 1 kHz band is at -139 dB (digital silence) against -22 to -28 dB just before it, and the tone is there. The source waveform around the three spans of the first run shows the whole word inside each span. The subtitles show `f******` and `t***` for the same words; `profanity_count` equals the number of bleeps.

**Subtitle sync.** Two checks. (1) The rendered audio was transcribed again with local `small` and the word starts compared with the stored transcript. Local transcript on clear speech: median difference 0.00 s, 90% within 0.04 s, which shows the window, trim and seek arithmetic adds no offset. Hosted `whisper-1` transcript: median 0.07 to 0.09 s, 90% within 0.31 to 0.41 s. (2) For words that follow a pause, the start of the sound in the waveform comes 0.06 to 0.08 s after the subtitle start on average with both transcribers (three clips; the fourth had only two such words). So subtitles are on time at the start of a phrase with both; inside a phrase the hosted word times are coarser (see open issues). On the noisy racing clip the second transcription differs in wording from the first, so only 42 of 61 words could be compared there (median 0.02 s, 8 beyond 0.3 s); that figure says little.

**Stills** (1 s, 5 s, middle, end card of each clip) were looked at after every change. Final state: captions inside the safe zone and readable, current word in the accent colour, keyword pop visible, hook box fits on one or two lines with its emoji, credit and watermark correct, LIVE badge on the spike-lane clips, progress bar, end card with the star and the series number.

### What changed after looking at real renders

1. **Emoji.** Montserrat has no emoji. libass took a fallback from the system fonts (Segoe UI Emoji on Windows), which the server image does not have. Emoji runs in the hook and the credit are now switched to the bundled Noto Emoji by name (`{\fnNoto Emoji}…{\fn}`), so no system font and no Dockerfile change is needed. Emoji are drawn in one colour (libass draws outlines only).
2. **LIVE badge dot.** Neither font has `●`. The dot is drawn as a shape; the badge text is `LIVE · JUST HAPPENED`.
3. **Progress bar in layout A.** At y = 1500 the bar ran across the streamer's face. In layout A it now runs along the seam: the seam is its white track and the accent bar grows over it, under the caption. Layout B keeps y = 1500.
4. **Word gaps.** The 6 px outline closed the gap between words; each space now gets 10 px more (`\fsp`).
5. **End card logo**: the star above the brand name.
6. **File size.** `superfast` with CRF 21 gave 48 MB for 31 s of fast gameplay (12 Mbit/s). A ceiling was added: `-maxrate 6M -bufsize 12M` (constants in `presets.py`). Files are now 15 to 29 MB.
7. **Layout B speed.** `drawbox` with alpha on the full 1080x1920 frame took two thirds of the render (22.8 s for a 20 s clip). The background is now darkened while it is still 270x480, before it is scaled up: 10.6 s, same picture.
8. **Loudness.** One-pass loudnorm gave -13.0 LUFS on an express clip, at the edge of the allowed range. Both modes now measure first (1 to 3 s, audio only) and feed the result to the render. A limiter at -1.5 dB follows loudnorm: in its linear mode it let the keyword pops through at -0.2 dBFS.
9. **Coarse hosted word times.** `whisper-1` often gives two or three words the same start. Those are spread evenly up to the next word (0.3 s each at most).
10. **Cut points.** The cut starts up to 0.15 s before the first word and ends 0.3 s after the last one, without entering the neighbouring words, so no syllable is clipped.
11. **Ducking.** A single 1-second frame flagged as music turned out to be speech over a game sound (Speech 0.77, Music 0.65), and ducking it removed a second of a sentence. Ducking now needs two flagged frames in a row. `music_ratio` still counts every flagged frame.
12. **No pop on a bleeped keyword.**

### Deviations from docs/09 and from the milestone file

1. **`clips.transcript` is in clip time**, not relative to the window start as docs/09 section 2 says. Nothing on the row says where the window started, so window-relative times could not be matched to the file; clip time is what the gate's sync check needs.
2. **Two-pass loudness in express mode too** (docs/09 section 6 says single-pass). Cost: 1.7 to 2.5 s.
3. **Progress bar on the seam in layout A** (docs/09 section 5 says y = 1500 for both layouts); the seam is white instead of accent.
4. **Constants that are not settings**, because no key exists: the bitrate ceiling (6M / 12M), the layout confidence 0.6, the limiter, the cut lead and tail, the minimum of two frames for ducking, the word gap. Proposed keys are listed below.
5. **Clip length limits for P2** are `spikes.min_len_s` / `spikes.max_len_s` narrowed by `min_len` / `max_len` of the lane's gate profile (hourly 20 to 60 s, express 15 to 45 s), so the writer does not make a clip the gate rejects for its length.
6. **A clip that P2 rejects, or that has no speech, is not rendered.** The row is closed as `rejected` in the factory. docs/09 runs the gate after the render; rendering first would only cost time.
7. **Transcription falls back to the other mode** when the first one fails, has no key or is over `transcribe.daily_budget_usd`.
8. **Translated words are spread in proportion to their length**, not evenly, so long words stay highlighted longer. Segments for P8 are built from the words (the transcription client returns no segments): a pause over 0.6 s, sentence punctuation, 8 s or 18 words end a segment.
9. **Storage through the REST API with httpx**, not the `supabase` Python client: same timeout, retry and logging code as the other clients, and testable with respx. The request shapes were read from `storage3` 2.34.1 and checked live.
10. **Upload is a separate step** (`upload_clip`, or `upload=True` on the input), because the milestone uploads after the gate.
11. **`render_ms`** is the ffmpeg time (loudness pass plus encode). The time of every stage is in the `clip.rendered` event.
12. **Music detection lives in `factory/music.py`**; `gate/music.py` is still the M07 stub. M07 can import `factory.music` or move it.
13. **Six-pointed star with narrow points** (inner radius 0.44 of the outer). The plain hexagram is a religious symbol, which a clips brand should not use by accident; the files in `assets/brand/` can be replaced.
14. `assets/subtitles/style.ass.tmpl` (docs/09 section 4) does not exist: the styles are generated in `subtitles.py` (static M06). `factory/profanity.py` of the milestone file is `factory/bleep.py`.

### Bugs found in other packages (worked around, not fixed)

- **Local transcription fails for every file with the locked dependencies.** faster-whisper 1.2.1 decodes files with PyAV and calls `av.open(..., metadata_errors=...)`; PyAV 19.0.2 (in `uv.lock`) no longer has that argument, so `Transcriber.transcribe(path, mode="local")` raises `TypeError`. The Docker image's self-check only loads the model, so it does not catch this. The factory avoids it by giving the model the samples instead of a path (`factory.transcript.whisper_factory`, passed to `Transcriber(model_factory=…)`). Any other caller of local transcription (the VOD fallback in M08) hits the bug unless it also uses `factory.transcript.default_transcriber()`.
- `clients/transcribe.extract_audio` is not used by the factory (it has no seek); `factory.tools.extract_audio` cuts the window.

### Open issues and what was not verified

- **Not run on the staging server.** The acceptance item "express render of a 30 s clip in 90 s or less on the staging server" was measured only on this desktop (9.6 s of ffmpeg, 40 s for the whole express pipeline in a fresh process).
- **Not run on Linux.** Docker is hung on this machine. The font lookup through `fontsdir`, the emoji font and the `movie` filter for the logo were rendered on Windows only. The font is addressed by name and by file, so no difference is expected, but it was not seen.
- **The `medium` Whisper model was not run** (only `small` and `base`); its speed and accuracy on the server are unknown.
- **NVENC**: the detection returned "not usable" on this machine (encoder compiled in, no NVIDIA GPU), which is the case it exists for. An encode with a real GPU was not tested.
- **P8 translation** was tested with fakes only; no non-English footage was rendered.
- **Hosted word times are coarse.** With `whisper-1` about one word in seven is more than 0.3 s away from the local model's time inside a phrase. Lines appear on time; the highlighted word can lag or lead. Groq's `whisper-large-v3-turbo` (no key yet) or a forced-alignment step would fix it.
- **Music false positives.** PANNs flagged one second of speech over game noise as music in three of six runs on the racing footage (ratio 0.03 to 0.05). With `gate.express.max_music_ratio = 0` one such frame makes a clip fail the express profile. M07 may want to ignore isolated frames, as the ducking now does.
- **The bleep pad is 0.05 s** (docs/09). In one case the word ended 0.01 s before the end of the span. A pad of 0.1 s would be safer against early word ends.
- A phrase keyword that covers a whole subtitle line shows the whole line in the accent colour (seen once: "Can they see me").
- The integration tests add about 2.5 minutes to the suite through the SSH tunnel (five ffmpeg renders).
