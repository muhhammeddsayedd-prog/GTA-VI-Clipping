## M05 — AI layer (prompts, schemas, calls, cost tracking)

**Date:** 2026-11-17 UTC · **Branch:** `m05-ai-layer` (from `m02-api-clients`: M00 to M03, static M06, Docker files)

### What was built

- `src/sixstars/ai/prompts/`: one Markdown file per prompt (`p1_spike_confirm.md` … `p8_translate_lines.md`), each with a `## System` and a `## User template` section, plus `_preamble.md` (the common first paragraph: brand "6 Stars Clips (@6starsclipping)", the game from `env.target_game`).
- `src/sixstars/ai/prompt_files.py`: loader (`load(prompt_id)`, cached), `Prompt.render_system(values)` and `Prompt.render_user(values)` (`str.format_map`; a missing placeholder raises `PromptFileError`).
- `src/sixstars/ai/schemas.py`: Pydantic reply models for P1 to P8 with the validators of the milestone, and per-call factories (`clip_writing_schema`, `spike_batch_schema`, `moment_list_schema`, `layout_schema`, `translated_segments_schema`) that add the limits of one call (window length, spike ids, frame size, segment count) so the client's repair retry also covers them.
- `src/sixstars/ai/calls.py`: the eight functions, input dataclasses, the budget guard (`BudgetExceededError`) and `enforce_policy` (code-side backstop for D20 and D21).
- `src/sixstars/ai/images.py`: `prepare_jpeg` (long side at most 1280 px, JPEG quality 85).
- `src/sixstars/ai/costs.py`: `today_spend(provider)`, `budget_remaining()`, `spend_by_operation(provider, since)`.
- `src/sixstars/ai/spike_confirm.py`: the tier rules of build step 5 (`decide`, pure) and `apply` (updates the `spikes` row, writes a `spike.confirmed` / `spike.rejected` event).
- Tests: 108 unit tests in `tests/unit/ai/` (fake client; malformed output through the real client with a scripted SDK stand-in: invalid then valid, invalid twice, trim outside the rules, box outside the frame, missing spike, wrong segment count), 5 integration tests in `tests/integration/test_ai_layer.py`, 17 live tests in `tests/live/test_ai_prompts.py`.
- Fixtures in `tests/fixtures/ai/`: `gta5_window_transcript.json` (the real caption track of 65 s of a public GTA 5 RP stream, words with times) and `live_cases.json` (hand-written chat samples, gambling, sponsored and spoiler segments, channel descriptions, emails, Spanish segments). No media is committed.

### Public API (what M04, M06, M07, M08, M09, M12 call)

```python
from sixstars.ai import calls, costs, spike_confirm
from sixstars.ai.calls import (BudgetExceededError, ChatLine, ClipContext, Segment, SpikeContext,
                               TranscriptChunk)
from sixstars.ai.schemas import (ClipWriting, Layout, Moment, PermissionVerdict, PixelBox, SafetyFlags,
                                 SpikeVerdict, TakedownVerdict, TranslatedSegment, VisualVerdict)

# lane: "vod" (default, stops with BudgetExceededError over ai.daily_budget_usd) or "express" (always runs)
calls.confirm_spikes(spikes: Sequence[SpikeContext], *, lane="vod", client=None) -> list[SpikeVerdict]
calls.write_clip(ctx: ClipContext, *, lane="vod", client=None) -> ClipWriting
calls.pick_moments(transcript_chunks: Sequence[TranscriptChunk], n_min, n_max, len_min, len_max, *,
                   title="", creator="", ref_id=None, client=None) -> list[Moment]        # always VOD budget
calls.detect_layout(frame_jpeg: bytes, w: int, h: int, *, lane="vod", ref_id=None, client=None) -> Layout
calls.visual_check(frames: Sequence[bytes], *, lane="vod", ref_id=None, client=None) -> VisualVerdict
calls.read_permission(description, name, titles, *, ref_id=None, client=None) -> PermissionVerdict  # VOD budget
calls.classify_takedown(sender, subject, body, *, ref_id=None, client=None) -> TakedownVerdict      # never blocked
calls.translate_segments(segments: Sequence[Segment], source_lang, *, lane="vod", ref_id=None,
                         client=None) -> list[TranslatedSegment]

SpikeContext(spike_id, creator, platform, stream_title, score_z, msgs, uniq, top_tokens=(), chat=(), transcript=None)
ChatLine(t_s, text, user=None)                 # t_s relative to the peak (P1) or to the window file (P2)
ClipContext(creator, platform, stream_title, lines, window_s, proposed_start_s, proposed_end_s, spike_floor_s,
            min_len_s, max_len_s, chat=(), verdict=None, profanity_hint=(), now=None,
            spoiler_block_until=None, reject_topics=None, clip_id=None)
TranscriptChunk(start_s, end_s, text);  Segment(start, end, text)

SpikeVerdict: is_moment, confidence, moment_type, one_line, noise_reason      (batch items also have spike_id)
ClipWriting:  start_s, end_s, hook, title, caption, hashtags, commentary, topic, keywords, spoiler,
              safety: SafetyFlags (.flagged() -> list[str]), score, score_parts, reject, reject_reason;
              .length_s, .keyword_map() -> dict[int, list[str]]   # the shape factory.subtitles takes
Moment:       start_s, end_s, moment_type, one_line, confidence
Layout:       facecam: PixelBox | None, gameplay: PixelBox, confidence        # original video pixels
VisualVerdict: other_watermark, platform_logos, menu_or_loading, pause_or_brb_screen, empty_facecam,
              readable_subtitles, notes; .problems() -> list[str]
PermissionVerdict: tier ("preferred" | "auto" | "restricted"), evidence
TakedownVerdict: is_takedown, kind, creator_handles, urls, platforms, summary
TranslatedSegment: start, end, en

spike_confirm.decide(provisional: "S"|"A"|"B", verdict, Thresholds) -> TierDecision(tier, status, confidence, reason)
spike_confirm.Thresholds.from_settings()       # spikes.s_min_confidence, spikes.ab_min_confidence
spike_confirm.apply(spike_id, provisional, verdict) -> TierDecision           # updates spikes + event

costs.today_spend(provider="anthropic") -> float;  costs.budget_remaining() -> float
costs.spend_by_operation(provider="anthropic", since=None) -> list[OperationSpend]
```

Notes for callers:

- `ClipContext.lines` takes `sixstars.factory.lines.Line` objects as they are (anything with `index`, `start_s`, `end_s`, `text`). All times are seconds from the start of the window file. `now`, `spoiler_block_until` and `reject_topics` default to the clock and to `gate.spoiler_block_until` / `gate.reject_topics`.
- `min_len_s` / `max_len_s` are passed by the caller (from `gate.hourly` / `gate.express` or `spikes.min_len_s` / `spikes.max_len_s`); `n_min` / `n_max` of `pick_moments` come from `vod.fallback_moments`.
- `write_clip` always returns a full `ClipWriting`, also for a rejected clip. `reject` is true when the model said so, when any safety flag is set, or when `spoiler` is true before `gate.spoiler_block_until` (`enforce_policy`). M07 should still check `score`, `safety.flagged()`, `spoiler` and its own keyword check on hook and title.
- Errors: `BudgetExceededError`, `InvalidModelOutput` (still invalid after the repair retry), `AnthropicRefusal` and `AnthropicError`; the first three are subclasses of the last. None is caught in `ai/`: the job retry rules decide.
- Usage rows: `api_usage.operation` is the prompt id (`p1_spike_confirm`, …), `ref_id` is the spike id (P1: the first one of a batch), `ClipContext.clip_id` (P2) or the `ref_id` argument.
- Models: `ai.model_fast` for P1, P5, P6, P7; `ai.model_writer` for P2, P3, P4, P8. Effort: `medium` for P2, P3, P4, `low` for the rest (constants `calls.EFFORT`, `calls.MAX_TOKENS`).

**My reading of the outputs.** Hooks, titles and captions are in English, hype in tone, inside the limits (hook at most 8 words, title at most 70 characters, caption at most 120, 3 to 5 lowercase hashtags) and contain none of the always-reject categories. One reply in about twenty broke the hook limit (9 words) and was repaired by the retry. The good moment scored 7 or 8 in every run and was never rejected; the gambling and sponsored segments were rejected in every run (6 of 6).

**What changed during iteration:**

1. `commentary` invented context once ("Streamer is playing dead…", not in the input). The rule now allows it only for a fact stated in the input; it has been null since.
2. `topic` had no fixed form. The rule now asks for 3 to 5 plain words (who, action, object), no creator or game name. It is steadier but still not identical between runs (see open issues).
3. The spoiler clip's hook and title hinted at the story ("He had to choose… and chose THIS", "picks the secret final mission option"). The rule now says these fields may talk only about the streamer's reaction. After the change 3 of 4 runs had no story detail; 1 of 4 still said "final mission" in the title. M07's keyword check on hook and title stays necessary.
4. The model compared the current date with the block date itself and got it wrong once in three runs (it rejected an allowed spoiler). The comparison is now done in code (`calls.spoiler_status`) and the prompt is told "BLOCKED until …" or "allowed".
5. P8 left Spanish laughter as "jajajaja"; it now writes "hahaha".
6. Keyword highlights are sometimes phrases that span two subtitle lines; code now drops any highlight that is not in the text of its line.

### Deviations from docs/15 and from the milestone file

1. **Prompt wording is written out in full.** docs/15 gives the task and rules of each prompt in a few lines; the files expand them (what counts as a moment, what each safety flag means, how to score) and say why each rule exists. The JSON shapes are those of docs/15. The schema is not repeated in the prompt files: the client appends the JSON Schema of the Pydantic model to the system prompt (M02), so the files have no JSON braces to escape.
2. **Handle `@6starsclipping`** (D101) instead of `@6starsclips`; the game name in the preamble comes from `env.target_game`, so staging prompts say "Grand Theft Auto V". The watermark named in P5 comes from `factory.watermark`.
3. **P1 batch template**: creator, platform and stream title are repeated in every spike block instead of once at the top, so one batch may hold spikes of different videos. `confidence` is defined as the probability that the spike is a clip-worthy moment (near 0 for clear noise), which is what the tier rules compare.
4. **P2 input**: the spoiler policy is sent as the current date plus a status computed in code ("BLOCKED until … UTC" or "allowed") instead of leaving the date comparison to the model. Subtitle lines are sent as `[n] start-end | text` (line times, not a time per word). Lines are 2 to 4 words, so cut points land on line boundaries. `profanity_hint` is an optional argument: no setting holds the list, the factory reads it from a file.
5. **P2 keywords**: a highlight may be a short phrase from the line (the subtitle renderer supports multi-word keywords). Keywords for a line that does not exist, or words that are not in their line, are dropped in code instead of failing the reply.
6. **P2 validation beyond the milestone list**: `commentary` at most 12 words, `topic` normalised to a slug, `score_parts` 1 to 10, at most 2 keywords per line, the trim checked against the window (inside the file, not after `spike_floor_s`, length between min and max). Hashtags: a leading `#`, capitals and repeats are tidied; a space or another character is an error.
7. **P3**: with several 30-minute slices the minimum per slice is 0 (a slice may have nothing good); the merged list is capped at `n_max`, overlaps dropped, strongest first. Fewer than `n_min` moments can come back: the prompt prefers no moment to a weak one.
8. **P4**: the frame is shrunk to at most 1280 px on the long side; the model answers in the pixels of the image it sees and the code scales the boxes to the original `w` x `h`. The returned `Layout` is in original pixels as docs/15 says.
9. **P5** accepts 1 to 8 frames (the gate sends 4).
10. **P7** is never blocked by the budget (a takedown must be handled). **P6** uses the VOD budget. **P3** has no `lane` argument (VOD lane only).
11. **P8**: the model must return one segment per input segment; the source `start` / `end` are kept in code whatever the model echoed. Batches of 60 segments.
12. **`spikes/confirm.py` was not written** (the task forbade edits in `src/sixstars/spikes/`). The glue is `sixstars.ai.spike_confirm` (`decide`, `apply`). M04 can import it from `spikes/confirm.py` or call it directly.
13. **`scripts/ai_smoke.py` was not written** (outside the allowed paths). `tests/live/test_ai_prompts.py` does the same job for all eight prompts and saves `layout_check.jpg`. No `ai` command group was added to `cli.py`: the milestone does not ask for one.
14. **Refusals** are not handled inside `ai/`: `AnthropicRefusal` reaches the caller. For P2 the safe reaction is to skip the clip.

### Open issues

- **`topic` is not a stable key.** The same moment written several times gave `new-player-robs-man-on-ground` and `player-caught-robbing-downed-player`. An exact match on `topic` (docs/10 duplicate check) will miss some repeats. M07 should compare topics by shared words (or rely on the same-source-range check for one source and use word overlap across sources).
- **P5 was checked on frames composed with Pillow** in the layout of our render (gameplay on top, facecam below, subtitle, watermark, credit), not on output of the M06 renderer, which is not finished on this branch. Re-run it on real renders in M07.
- **P4 was checked on one stream layout** (facecam top-left over full-screen gameplay). Layouts with the game in a panel, or with no facecam, are covered only by unit tests.
- **P2 scores** for the real moment were 7 or 8 across about ten runs: it passes the hourly gate (7) but not always the express gate (8). Whether 8 is the right express bar needs real data from staging.
- The live inputs for gambling, sponsored and spoiler segments are hand-written. Real segments are longer and less explicit; the code backstop only helps when the model sets the flag.
- Prompt caching: the P2 system block is about 3,500 tokens and is read from cache on repeat calls (`cache_read_tokens` 3,532 in the logs). The fast-model prompts are shorter than the minimum cacheable length on Haiku, so they are not cached; at $0.10 per million input tokens this does not matter.

### Bugs found elsewhere (not fixed)

- No functional bug found in the clients or the fakes.
- One gap in `clients/anthropic_client.py`: the `invalid_model_output` warning does not log why the reply was invalid (only the prompt id and stop reason), so a prompt that often needs the repair retry is hard to diagnose from logs. Adding the first 200 characters of the validation problem would help.
- `tests/live/conftest.py` blanks `DATABASE_URL`, so the M02 live tests never write `api_usage`. The AI live tests set it again from `AI_LIVE_DATABASE_URL` (and refuse a Supabase host) so the spend can be read back.
