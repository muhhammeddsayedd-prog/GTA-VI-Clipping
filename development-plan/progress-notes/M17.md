# M17 — Admin console: progress notes (2026-11-17)

**Built** (branch `m17-admin-console`, D109, `docs/26-admin-console.md`)

- **Control API**
  - Read-only `/v1/admin/*` routes, in `api/routes_admin.py` and `api/admin_queries.py`.
  - Every request runs in one read-only transaction with a statement timeout.
  - A new `DASHBOARD_API_TOKEN` is accepted everywhere except the five trigger routes, which keep n8n's token only.
  - The request log line now carries `actor` = `n8n` | `dashboard`.
  - Migration `0018_admin_console.sql` only inserts settings: `admin.statement_timeout_ms`, `admin.list_max_limit`, `admin.month_ceiling_usd` and `admin.noisy_event_types`.
- **`web/`**: a Next.js 16 console with every screen from the approved mockups, plus modals, drawers, the command palette and mobile layouts.
  - **Auth:** Supabase Auth, single operator (`ADMIN_EMAIL`). A dev login and generated sample data are available locally only, never on Vercel.
  - **API access:** a backend-for-frontend proxy with an allowlist and a same-origin check on writes; the token stays on the server.
  - **Animations:** React Bits components, vendored in `components/reactbits/`.
- **CI:** a new `web` job runs lint, types, vitest, the build, and a check that no secret name is in a client bundle.

**Verified**

- **Checks:** ruff, ruff format, `mypy --strict`, API unit tests, web lint, tsc, vitest (11) and `next build` all pass. Every console route renders per request; none is prerendered.
- **End to end:** the console ran against the real API on a throwaway Postgres seeded with the integration world.
  - All 27 pages loaded with no console errors and no failed proxy calls.
  - Stop and resume went through the UI and wrote `control.stop` / `control.start`.
  - A settings edit through the UI wrote `setting.changed` (`posting.min_gap_s` 900 → 960).
- **Refusals:**
  - wrong password, and a different email, both get the same generic error;
  - no session gives 401 on the API and a redirect from pages;
  - a trigger route through the proxy gives 404;
  - path traversal gives 404;
  - a cross-site POST gives 403;
  - the dashboard token on a trigger route gives 401.

**Deviations and open issues**

- **Contract details:**
  - API errors are `{error, code, request_id}`.
  - `accounts` and `settings` answer `{items}`.
  - The live-session detail returns the spike list as `spikes_list`; `spikes` stays the S/A/B counts.
  - `posts` gained a `clip_id` filter.
- **Missing from the contract:**
  - no chat-rate series for live and VOD timelines, so they show spike markers only;
  - no spike weights;
  - no per-stage render timing;
  - no views history per post.
- **Missing index:** there is no index on `events(entity_type, entity_id)`, so detail event lists scan the table, bounded by the statement timeout. Add it in a follow-up migration.
- **Integration tests:** 2 gate tests failed locally on Windows (`test_black_frames_are_rejected`, `test_a_clip_rejected_for_another_reason_is_not_scored`). They are not touched by M17; confirm on CI.
- **Not deployed yet:** staging needs, in this order:
  1. the PR merged to `develop`, which deploys the API to the staging server;
  2. `DASHBOARD_API_TOKEN` in `/opt/6stars/.env`;
  3. Supabase staging Auth: sign-ups off and the operator user created;
  4. a Vercel project with Root Directory `web` and the env vars from `web/.env.example`.
